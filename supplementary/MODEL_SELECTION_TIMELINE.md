# Model-selection and split-use timeline | pSMP-rnp-resource-v0.1

Honest disclosure of which splits influenced which decisions. Dates are approximate freeze chronology (resource freeze date 2026-07-16).

## Declared splits

| Split | n | Intended role |
|-------|---|----------------|
| train200 | 200 | Fine-tuning pool; low-data subsets at 10/25/50/100% (seed 42) |
| val50 | 50 | Public evaluation pool in v0.1 |
| spotlight10 / test10 | 10 ⊂ val50 | Descriptive spotlight; **not** used for checkpoint or recipe selection |
| dev40 | 40 = val50 − test10 | Ablation / development comparisons (all-mix vs controls, five-sample probes) |
| Temporal candidates | 107 (≥2024-07) | Extension screen; Temporal5 = operational shortlist |

| Decision | Influenced by | Status for v0.1 reporting |

## Consequence for estimands

Because all-mix / step schedule were informed by development readouts overlapping **dev40 ⊂ val50**, the published val50 paired table is best described as:

> **public development-benchmark results for a frozen protocol**, not as a fully isolated confirmatory test.

v0.1 mitigation (text + resource):

1. Label val50 as the public development benchmark in Methods / Limitations.
2. Keep spotlight10 unused for selection (already stated).
3. Ship failure-aware and neighbor audits on the full val50.
4. Reserve a **temporal or cluster-disjoint holdout** (list freeze first; score after recipe lock) for the next resource version — do not tune on it.
